* Identity platform
** TODO Initialise OpenBao and store the unseal shares offline
:PROPERTIES:
:ADDED: 2026-08-29
:BLOCKS: everything else in OpenBao
:END:

OpenBao is deployed, running, and *sealed and uninitialised* — the correct state
before first use. Initialisation mints the unseal shares and the root token;
both are key material that must not be generated by, or stored on, the machine
they protect, so no unit can do this for you.

Reach it over the tailnet from Dracula. The =bao= client is in
=hm-modules/packages.nix=, so rebuild Dracula once if you have not since
2026-08-29:

#+begin_src bash
sudo nixos-rebuild switch --flake ~/nixos-config#dracula
#+end_src

The listener is plain HTTP on the tailnet port — Tailscale passes TCP through
untouched and WireGuard already encrypts it, so there is no second TLS layer:

#+begin_src bash
set -x BAO_ADDR http://alucard.tailf117a1.ts.net:28200   # fish
bao operator init -key-shares=3 -key-threshold=2
#+end_src

In bash/zsh use =export BAO_ADDR=http://alucard.tailf117a1.ts.net:28200=.

Confirm you are talking to the right box first — this should report
=initialized: false, sealed: true=:

#+begin_src bash
curl -s $BAO_ADDR/v1/sys/health | jq
#+end_src

If you would rather not install anything, run it on the server instead, where
the CLI ships with the service:

#+begin_src bash
ssh -t Bereitserver 'BAO_ADDR=http://127.0.0.1:8200 bao operator init -key-shares=3 -key-threshold=2'
#+end_src

Then:
- Put the three unseal shares in *three different places*, at least one offline
  and not on Alucard (password manager, printed copy, second machine).
- Store the initial root token in your password manager, then create a named
  admin identity and *revoke the root token*.
- Two of three shares are needed to unseal. One share on its own is useless,
  which is the point.

After every reboot OpenBao comes back sealed. Unseal with:

#+begin_src bash
ssh Bereitserver 'bao-status'          # confirms Sealed: true
env BAO_ADDR=http://alucard.tailf117a1.ts.net:28200 bao operator unseal   # twice
#+end_src

There is deliberately no auto-unseal: a single node has no KMS or second Bao to
unseal against, and an unseal key stored beside the ciphertext it protects makes
the seal decorative.

** TODO Enable OpenBao snapshot backups
:PROPERTIES:
:ADDED: 2026-08-29
:DEPENDS: OpenBao initialisation
:END:

A Raft snapshot is an *authenticated API call*, so the backup job cannot exist
before the cluster does. Once initialised:

1. Create a policy allowing only =sys/storage/raft/snapshot= (read).
2. Issue a periodic token bound to that policy.
3. Store it: =sops secrets/dmbs.yaml= under =openbao/snapshot_token=.
4. Set =services.localOpenBao.snapshotBackup.enable = true;= in
   [[file:../hosts/alucard/default.nix][hosts/alucard/default.nix]] and rebuild.

The job then joins the same restic repository family as Keycloak, n8n and
Paperless, with the same restore drill.

Until this is done, *OpenBao has no backup*. Do not put anything in it that is
not also recoverable from elsewhere.

** TODO Wire Teleport to GitHub SSO
:PROPERTIES:
:ADDED: 2026-08-29
:DECISION: Community Edition + GitHub SSO (recorded 2026-08-29)
:END:

Teleport Community supports exactly one external connector: GitHub. Keycloak
OIDC is Enterprise-gated, which is why administrator identity lives in GitHub
while Keycloak stays the *application* IdP.

1. Create a GitHub OAuth app:
   - Homepage: =https://alucard.tailf117a1.ts.net:33080=
   - Callback: =https://alucard.tailf117a1.ts.net:33080/v1/webapi/github/callback=
2. Put the client secret in SOPS, then create the connector resource with
   =tctl create= mapping your GitHub org/team to Teleport roles.
3. Flip =authentication.type= from ="local"= to ="github"= in
   [[file:../modules/teleport.nix][modules/teleport.nix]] and rebuild.

Keep at least one local user with =editor= so a GitHub outage cannot lock you
out of your own cluster.

*Two things to expect after installing:*

- =schedule= is ="* 22-23 * * 1-5"=, so Renovate only acts on weekday evenings

  dashboard issue. Read-only access produces silence.
That is the whole task — nothing in the repo needs changing. The config was
validated with =renovate-config-validator=, and every custom manager was tested

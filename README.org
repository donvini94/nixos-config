* Build and deploy

#+begin_src sh
nix flake check
nix build --no-link .#nixosConfigurations.dracula.config.system.build.toplevel
nix build --no-link .#nixosConfigurations.alucard.config.system.build.toplevel
nix build --no-link '.#darwinConfigurations.AC-0137.system'

ssh dracula 'sudo -n /run/current-system/sw/bin/nixos-rebuild switch --flake /home/vincenzo/nixos-config#dracula'
ssh alucard 'sudo -n /run/current-system/sw/bin/nixos-rebuild switch --flake /home/vincenzo/nixos-config#alucard'
sudo -n /run/current-system/sw/bin/darwin-rebuild switch --flake /Users/vincenzopace/nixos-config#AC-0137
#+end_src

The agent commits, pushes, synchronizes the checkouts and switches affected hosts.
The exact commands above are passwordless; relative flake paths do not match sudo policy.
=nix flake check= runs shell lint, Python undefined/unused-name checks,
model-download, agent-tool and client-independence checks on Linux or macOS.
CI runs these checks, evaluates host build plans and builds exposed local packages;
a plan is not a full build.
Renovate owns flake inputs, OCI digests and action pins. =package-update.yml= owns
=packages/= and =coding-agents/packages/= version/hash updates, including OMP on Linux.
=update-skills check|apply [SKILL...]= refreshes vendored skill files from
=coding-agents/skills/sources.json=; it changes neither package versions nor client state.
Linear's skill follows its flake package version; Zotero's version is declared in
=coding-agents/skills/sources.json= and used by =hm-modules/zotero-cli.nix=.
Locally authored skills are not updater targets.

* Agent clients

=programs.ompClient.enable= and =programs.piClient.enable= independently select
OMP and Pi in each host's home configuration. OMP remains available for research.
=coding-agents/home/omp.nix= and =coding-agents/home/omp-clients.nix= own OMP configuration;
=coding-agents/home/pi.nix= owns Pi configuration. Neither launches the other.
Settings, authentication, sessions and memory remain in each client's own directory
(=~/.omp/agent/= or =~/.pi/agent/=). Pi's MCP configuration and writable
=AGENTS.md=/=MEMORY.md= are not replaced by activation.

Mentor, learning and prompt-snippet source packages live under
=~/.local/share/agent-content/=, managed by =coding-agents/home/agent-content.nix=.
Their Pi and OMP entry points use separate client state. Activation fast-forwards
clean source checkouts and leaves dirty or diverged ones untouched.
Shared engineering and scoped domain instructions are in =coding-agents/guidance/=. OMP
links rules for automatic loading within their declared scopes. Other clients
read the same files through shared skills without OMP rule URLs.
Pi deliberately excludes the automatic =~/.agents/skills/= tree.

Pi settings are seeded as defaults; existing native selections win on activation.
Declared model definitions are refreshed without removing extra user providers.
Use =pi install/remove= and =pi update --extensions= for Pi packages, and OMP's
native plugin manager for OMP plugins. =update-skills= manages neither client.
Pi's binary version is pinned in =coding-agents/home/pi.nix=. The Mac's OMP binary is its native
Bun installation; its wrapper scopes the managed settings to OMP invocations.

* Startup applications

The stack stays in this repository. Nix owns deployment, service identities, private
listeners, approved egress and secrets. Application preferences and authored state
remain writable; exporting/restoring that state is part of moving an instance.

Clients talk to Requesty directly with a per-host key (=services.requesty.apiKeyFile=,
SOPS-owned); spend, access and the approved-model catalog are managed in Requesty.
OMP discovers models natively (=openai-models-list=), Pi through the pinned
=pi-requesty= extension, Hermes through its provider config. The initial default model
is in =services.requesty.{endpoint,defaultModel}= in =coding-agents/nixos/requesty.nix=; local model metadata stays declarative.

Hermes runs the upstream image (ai-stack's =nixos/hermes.nix=) as one host-network container
with its data in =/var/lib/hermes-agent=. Nix pins the image and supplies the initial
credentials, mounts and loopback bindings; settings, MCP servers and tools are managed in
the dashboard and persist in that directory, where saved values override the SOPS ones.
The agent reaches host services and the public internet; its UID is blocked from other
machines, the tailnet, metadata and SMTP (=services.aiStack.egress=). The container is
not a security boundary against it.

Base images and application packages are pinned. UI-installed tools and workflow edits
are mutable state, not automatically reproducible builds: record their versions and
configuration before relying on them in another deployment. The n8n state directory
is configurable rather than tied to Alucard. n8n runs as one host-network container
(internal task runner); workflows and credentials live in its UI and database.

Alucard is =tag:monitoring= in the tailnet; the tailnet policy lives in the private
=donvini94/fleet= repository (=tailnet/policy.hujson=, applied on merge).
Admin interfaces bind loopback and are published through Tailscale Serve; inspect
=tailscale serve status= for addresses. Do not enable Funnel. Docker wildcard
port publishing can bypass the host firewall; firewall assertions cannot prove
that externally maintained Compose stacks are private.
qBittorrent uses Gluetun's VPN namespace; do not give it an independent network.

Mailcow (=/opt/mailcow-dockerized=) and Actual Budget (=~/actual_budget=) are
maintained outside this repository. Onyx runs from the ai-stack's Onyx feature. Back up first
and use their supported migration/update procedures, not generic image restarts.

=systemctl restart ai-stack.target= restarts Alucard's Hermes and n8n together.
Hermes sessions are separate but memory/workspace are shared by the founders;
this is not a tenant boundary.

* Secrets and recovery

Edit =secrets/*.yaml= with =sops=; runtime plaintext belongs under =/run/secrets=,
never in the Nix store. Keep age private keys backed up separately.
- n8n encryption keys and restic passwords require a
  supported migration, not just an edited SOPS value.
- Database and administrator bootstrap passwords do not update existing accounts.
- Hermes values saved in the UI override the SOPS ones; clear them there to rotate via SOPS.
- Paperless is configured in its web UI (tags, rules, workflows, mail accounts); the nightly
  export is the portable copy. Seed another instance with =paperless-manage document_importer
  --data-only= on a manifest holding only configuration records, and re-enter mail passwords.
  Bulk classification is Paperless' own =paperless-manage document_retagger --use-first
  --suggest -c -t -T=.

=systemctl list-timers 'restic-backups-*'= shows the restic jobs (Keycloak, Jellyfin, n8n,
Hermes, Paperless; repositories under =/mnt/hetzner/restic/=). Restoring files is not proof of application recovery;
test database imports and application logins before relying on a migration rollback.
Media application state and services outside Nix need their own backup coverage.

Mail uses one Alucard notmuch hub and two muchsync replicas; recovery and sync
constraints are in [[file:mail/README.md][mail/README.md]]. Outstanding manual work is in
[[file:docs/OPERATOR-ACTIONS.org][OPERATOR-ACTIONS.org]].

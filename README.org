#+TITLE: NixOS Configuration
#+DESCRIPTION: Flake-based NixOS config for a desktop (dracula) and home server (alucard)

* Overview

Flake-based NixOS configuration managing two systems:
- *dracula* — Desktop workstation (AMD CPU, NVIDIA RTX 3090, Hyprland + caelestia-shell), also the local LLM inference host
- *alucard* — Hetzner OpenStack VM: public nginx edge, Docker media stack, document management, mail, and a private agent/automation stack

The flake provides two host-builder functions:
- =mkDesktopHost "hostname"= — Full desktop with Hyprland, home-manager, sops, hosts blocking
- =mkServerHost "hostname"= — Minimal server (host imports what it needs)

Both hosts share one AI ingress module, one observability stack, and one container-update
mechanism; each parameterises them differently. Every AI and admin surface binds loopback —
nothing in the AI stack is published on a public domain, and on alucard the only remote entry
point is Tailscale.

Detailed operator documentation lives in [[file:docs/][docs/]]; module conventions in [[file:AGENTS.md][AGENTS.md]].

* AI Stack

One module, =modules/ai-ingress.nix=, defines the contract on both hosts: an
OpenAI-compatible logging proxy on =127.0.0.1:8080= that every client speaks to. It is the
single chokepoint for caller attribution (=X-AI-Caller=), token accounting, cost, the JSONL
audit log, Prometheus metrics, and Langfuse traces. The module *asserts* the bind address is
loopback. Only the backend behind it differs per host.

#+begin_src
dracula:  omp / opencode / Hermes / n8n
              → local-llama-logger  127.0.0.1:8080
              → local-llama-swap    127.0.0.1:18080
              → llama-server        127.0.0.1:18100+   (loaded on demand)

alucard:  omp / opencode / Hermes / n8n
              → local-llama-logger  127.0.0.1:8080
              → https://router.requesty.ai
#+end_src

** Models

Dracula serves two pinned GGUFs (HF revision + sha256, auto-downloaded and verified into
=/var/lib/llama/models=), swapped on demand by llama-swap:

| Model ID                 | Context | Default |
|--------------------------+---------+---------|
| =dirk-qwen3.8-27b-local= |   32768 | yes     |
| =qwen3.6-35b-a3b=        |   65536 | no      |

Alucard carries the only server-side upstream credential (Requesty). Its model allowlist and
price map come from =lib/requesty-models.nix=, and =modules/remote-openai.nix= refuses to start
if that list drifts from the authenticated =/v1/models= catalog. Dracula holds *no* Requesty
key — its clients reach Alucard's authenticated ingress over Tailscale instead.

** Agents and automation

- *Hermes* — NousResearch's =hermes-agent=, a pinned flake input, run as a hardened Docker
  container. Dracula runs a personal single-operator agent against the local model; Alucard
  runs a separate shared instance against Requesty. They share no state. API on =:8642=
  (bearer auth), dashboard on =:9119= (basic auth). On alucard, Telegram is the only chat
  transport, and its egress goes through a tinyproxy allowlist (=:18084=) permitting exactly
  two hosts.
- *n8n* — containerised, read-only, cap-drop-ALL, on a private bridge. It reaches the ingress
  and the Hermes API only through systemd socket proxies bound to the bridge gateway, never a
  host NIC. Workflows are reviewed JSON in =n8n/workflows/<host>/= and imported with
  =n8n-workflows=.
- *Lifecycle* — everything is grouped under =ai-stack.target=. Members of group =llama=
  (=services.aiIngress.operators=) start and stop it without root via a polkit rule.

** Private access (Tailscale)

No Funnel, no exit node, no subnet routes. =tailscale serve= publishes loopback ports onto
=alucard.tailf117a1.ts.net= and nothing else:

| Tailnet port | Service          |
|--------------+------------------|
|        23000 | Langfuse         |
|        23001 | Grafana          |
|        25678 | n8n              |
|        28080 | AI ingress       |
|        29091 | Prometheus       |
|        29119 | Hermes dashboard |

Each media app keeps its own loopback port number on the tailnet: Kapowarr 15656, Bazarr
16767, Radarr 17878, qBittorrent 18080, Sonarr 18989, SABnzbd 19090, Prowlarr 19696.

The Hermes dashboard needs browser WebSockets, so it is the one HTTPS map: tailnet =:29119=
→ an internal nginx vhost that rewrites =Host=/=Origin= and returns 403 for any other origin
→ =127.0.0.1:9119=.

** Documents

=modules/paperless.nix= runs Paperless-ngx plus an idempotent provisioner
(=paperless/provision.py=) that reconciles tags, correspondents, document types, workflows and
saved views from =paperless/taxonomy.yaml= (public) and =secrets/paperless.yaml= (private). It
upserts by name and never deletes — drift is reported, not applied. Nightly exports are pushed
off-site to the Hetzner storage box with restic, and a separate unit restores the latest
snapshot and verifies its contents.

* Security (alucard)

Three independent layers, each in its own file:

| Layer     | Implementation                                                       | File             |
|-----------+----------------------------------------------------------------------+------------------|
| L7 WAF    | ModSecurity + OWASP CRS (pinned release), audit log, rate/conn zones | =security.nix=   |
| L3/L4 IDS | CrowdSec agent + firewall bouncer on =INPUT= and =DOCKER-USER=       | =security.nix=   |
| SSH       | fail2ban, key-only auth, no root login                               | =networking.nix= |

Plus: outbound mining-pool port blocks in the firewall, a =mining-watchdog= unit that stops
any container found talking to a pool port, and a daily Trivy scan of every running image
(root *and* rootless daemons) whose results land in Prometheus as textfile metrics.

CRS exemptions are surgical and each documents a verified false positive in a comment next to
the rule. Because nginx evaluates the server-level WAF before a nested location can re-enable
it, the pattern is =modsecurity off= at the vhost and =modsecurity on= on the catch-all route.

* Observability

=modules/observability.nix= drives one digest-pinned compose stack, identical on both hosts
and parameterised per host (GPU metrics on dracula only):

| Component     |  Port | Purpose                                           |
|---------------+-------+---------------------------------------------------|
| Langfuse      | 13000 | LLM traces (+ postgres, clickhouse, redis, minio) |
| Grafana       | 13001 | Provisioned "AI and machine overview" dashboard   |
| Prometheus    | 19091 | 90 d / 20 GB retention                            |
| node-exporter | 19100 | Host metrics + textfile collector                 |
| cAdvisor      | 18081 | Container metrics                                 |
| DCGM exporter | 19400 | GPU metrics (compose profile =gpu=, dracula)      |

Scrape targets: the AI ingress, n8n, CrowdSec, node, containers, and Prometheus itself. The
dashboard renders inference latency/TTFT/cost next to Trivy vulnerability counts, so security
and AI telemetry close the loop in the same place. Cost is reported on two deliberately
non-summable tracks — provider-billed and list-price estimate; local models report neither
rather than a fake =$0.00=.

* CI and Supply Chain

- =.github/workflows/nix-build.yml= builds =nixosConfigurations.{dracula,alucard}.config.system.build.toplevel=
  on every PR and push to master, and runs =nix flake check= as a separate job.
- =nix flake check= runs both the package-patch guard and the AI ingress regression suite.
  =scripts/check-no-package-patches.sh= rejects =overrideAttrs=, =postPatch=, =applyPatches=,
  ~patches =~ assignments and locally defined overlay lambdas. The allow-list is currently
  *empty*: the libmodsecurity mutation was dropped on 2026-08-29 once nixpkgs stopped building
  =pcre2= with =--enable-jit-sealloc=. Any future exception must carry an =# UPSTREAM DEFECT=
  comment or the check fails anyway.
- =renovate.json= is configured to pin container digests and GitHub Action SHAs with
  =automerge: false=, so a reviewed Git commit is the only path a container image changes.
  Renovate is installed and [[https://github.com/donvini94/nixos-config/issues/1][Dependency Dashboard issue #1]] exists.
  Updates remain non-automerge and use the configured weekday 22:00–23:00 Europe/Berlin
  schedule; see =docs/OPERATOR-ACTIONS.org=.

* Secret Management

Uses [[https://github.com/Mic92/sops-nix][sops-nix]] with age encryption. Three recipient keys (desktop, server, macbook). Secrets are
delivered to services via systemd =LoadCredential= or sops templates, never plain env vars in
the store.

#+begin_src bash
sops secrets/dmbs.yaml          # Base host secrets
sops secrets/alucard-ai.yaml    # Server AI stack (Requesty, n8n, Langfuse, Hermes)
sops secrets/dracula-ai.yaml    # Desktop AI stack
sops secrets/paperless.yaml     # Private half of the Paperless taxonomy
#+end_src

* Adding a New Desktop Host

#+begin_src nix
# 1. In flake.nix, add one line:
newhost = mkDesktopHost "newhost";
#+end_src

#+begin_src bash
# 2. Create the host directory:
mkdir -p hosts/newhost
#+end_src

#+begin_src nix
# 3. hosts/newhost/default.nix — import shared modules + set identity:
{ lib, pkgs, username, ... }:
{
  imports = [
    ../../modules/desktop.nix    # Full desktop stack
    ../../modules/nvidia.nix     # Opt-in: only for NVIDIA GPUs
    ../../modules/gaming.nix     # Opt-in: Steam, Wine, etc.
    ./hardware.nix
  ];
  networking.hostName = "newhost";
  users.users."${username}" = {
    isNormalUser = true;
    extraGroups = [ "networkmanager" "wheel" ];
    packages = with pkgs; [ firefox ];
  };
  system.stateVersion = "24.11";
}
#+end_src

#+begin_src bash
# 4. Generate hardware config on the target machine:
nixos-generate-config --show-hardware-config > hosts/newhost/hardware.nix
#+end_src

#+begin_src bash
# 5. Build and switch:
sudo nixos-rebuild switch --flake .#newhost
#+end_src

* Adapting This Config

1. Fork and clone
2. Create your host under =hosts/<name>/= following the pattern above
3. Enable/disable opt-in modules (=nvidia.nix=, =gaming.nix=) as needed
4. For a server: adapt =hosts/alucard/= — each file is self-contained
5. For the AI stack: import =modules/ai-ingress.nix= plus exactly one backend
   (=llama.nix= for local GGUFs, =remote-openai.nix= for a hosted router)
6. Set up your own sops-nix age keys in =.sops.yaml= and re-encrypt secrets
